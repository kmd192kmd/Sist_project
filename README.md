# 🏫 교육센터 운영 관리 시스템 (Oracle Database Project)

쌍용 교육 센터의 과정을 관리하고 교육생의 성적, 출결 및 사후 처리를 통합 관리하는 데이터베이스 기반 시스템입니다.

## 💡 3. ERD 수정 및 고도화 사례 (데이터 설계 및 협업)
프로젝트 데이터 설계 과정에서 발견된 문제점을 분석하고, 데이터 무결성과 쿼리 성능을 향상시키기 위해 모델을 리팩토링한 사례입니다.

### 📝 사례 1: 시험 테이블 설계 (정규화 vs 반정규화 비교 분석)
- **설계 고민**: 수강생 성적 조회 시의 쿼리 성능과 향후 새로운 시험 유형 추가에 대비한 확장성 사이에서 트레이드오프를 분석했습니다.
- **정규화 모델 고려**: '시험 유형' 컬럼을 통합하여 NULL 값을 최소화하고 데이터 무결성을 유지하려 했으나, 성적 조회 시 여러 행을 조회(JOIN 또는 다중 행 처리)해야 하는 단점이 발견되었습니다.
- **반정규화 모델 적용**: 한 행에서 필기와 실기 점수를 동시에 조회하여 성능을 향상시키고, 수강생별 성적표 출력 쿼리를 단순화/효율화하기 위해 '필기'와 '실기' 컬럼을 분리하는 반정규화 구조를 채택했습니다.

### 🔗 사례 2: 수강생-취업성공수당 관계의 재정의
- **문제 발견**: 초기 설계에서는 '취업성공수당' 테이블이 '취업상태' 테이블의 하위로 직접 연결되어 있었습니다.
- **해결 및 구조 변경**: 취업성공수당은 특정 취업 상태(예: 재직, 퇴사 등)에 귀속되는 것이 아니라, 수강생 본인에게 단 한 번만 지급되는 정보입니다. 따라서 취업성공수당 테이블을 수강생 테이블과 **직접 1:1 관계**로 연결하도록 구조를 전면 수정했습니다.
- **기대 효과**: 이 수정을 통해 수강생당 단 한 번만 지급된다는 비즈니스 제약을 데이터베이스 구조적으로 보장(데이터 무결성 향상)하였으며, 취업 상태의 변경과 무관하게 수당 지급 이력을 독립적으로 관리할 수 있어 유지보수성이 크게 향상되었습니다.

## 🔑 4. 주요 기능 요구사항

### 🛡 관리자 (Admin)
- **기초 정보 및 계정 관리**: 과정, 과목, 강의실, 교사 및 교육생 정보 CRUD
- **개설 관리**: 과정 및 과목 개설, 강의실 및 교사 배정
- **성적/출결 모니터링**: 전체 교육생의 성적 조회 및 기간별 출결 현황 분석
- **사후 처리 지원**: 취업 현황 파악 및 취업성공수당 지급 관리 여부 확인

### 👨‍🏫 교사 (Teacher)
- **강의 스케줄**: 담당 과정의 강의 예정/중/종료 상태 확인
- **성적 관리**: 과목별 배점(출결, 필기, 실기) 등록 및 교육생 성적 입력
- **출결 관리**: 담당 교육생의 근태 조회 및 관리

### 👨‍🎓 교육생 (Student)
- **정보 및 성적 조회**: 본인의 수강 정보, 교재, 강사 정보 및 과목별 취득 점수 확인
- **출결 및 사후처리**: 일일 출퇴근 기록, 본인의 취업 활동 및 취업성공수당 지급 현황 확인

## 🛠 5. 기술적 구현 세부사항

### 1️⃣ Tables & DDL
- 데이터 의존성을 고려한 **5단계 계층 구조** 설계
- 참조 무결성(FK)을 보장하는 정교한 제약 조건 설정

### 2️⃣ Java 기반 정교한 더미 데이터 생성
현실적인 데이터 환경을 위해 Java 프로그램을 작성하여 대량의 DML을 자동화했습니다.
- **Attendance.java**: 법정 공휴일 및 주말 제외 로직 적용. 난수(Random) 알고리즘을 통한 현실적 근태 확률(정상 85%, 지각 10%, 결석 5%) 반영 및 시간(`TO_DATE`) 자동 계산.
- **Instructor.java**: 성/이름 배열 3중 Loop 조합을 통한 고유 교사 성명 생성. 중복 방지 로직이 적용된 주민등록번호 및 전화번호 자동 생성기 구현.
- **Student.java**: 식별자(Sequence)를 활용하여 대규모 수강생의 "수강대기" 상태 및 기본 정보 일괄 `INSERT` 쿼리 생성.

### 3️⃣ PL/SQL 및 비즈니스 로직
- **프로시저**: 교육생 성적 일괄 산출 및 수료 처리 자동화
- **트리거**: 출결 기록 시 실시간 근태 상태(지각, 조퇴 등) 자동 판별

## 🗃 6. 데이터베이스 명명 규칙 (Naming Rule)
- **Table**: 대문자 및 언더스코어(`_`) 사용 (예: `REGISTERED_COURSE`)
- **Column**: 카멜 케이스(`camelCase`) 사용 (예: `registeredCourseSeq`)
